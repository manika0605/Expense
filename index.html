What is Claude?

🤖

AI Assistant

Claude is an AI assistant built by Anthropic. It can help with writing, analysis, coding, math, reasoning, and much more. It's designed to be helpful, harmless, and honest.

🔒

Safety-First Design

Anthropic focuses on AI safety research. Claude is built with Constitutional AI principles, making it more reliable, interpretable, and steerable than many alternatives.

🚀

Capabilities

  • Natural language understanding & generation
  • Code writing, review, and debugging
  • Data analysis and reasoning
  • Document summarization
  • Creative and technical writing
  • Multi-turn conversation with context

Claude Model Family

Choose the right model for your use case

Model Best For Speed Intelligence
Opus 4.6 Complex reasoning, coding, deep analysis
Sonnet 4.6 Balanced performance for most tasks
Haiku 4.5 Fast responses, simple tasks, high volume
Tip: When building AI applications, default to the latest and most capable Claude models. Use Haiku for latency-sensitive or high-volume tasks where cost matters.

Claude Code

Anthropic's official agentic coding tool

What is Claude Code?

Claude Code is an agentic coding tool that lives in your terminal and IDE. It understands your entire codebase, can execute commands, edit files, and help you build software end-to-end.

✍️

Available Everywhere

  • CLI in the terminal
  • Desktop app (Mac/Windows)
  • Web app (claude.ai/code)
  • VS Code extension
  • JetBrains extension
🛠

Key Features

  • Read, search, and edit files
  • Run terminal commands
  • Git operations (commits, PRs)
  • Multi-file refactoring
  • Test writing and debugging
  • Codebase exploration

Essential Slash Commands

Claude Code Deep Dive

Understand the core concepts that power your Claude Code workflow

📁

.claude Directory

The .claude/ directory is Claude Code's configuration home. It lives at ~/.claude/ globally and can also exist per-project. It stores your settings, memory, and customizations.

~/.claude/
  • settings.json — Global settings, permissions, and hook definitions
  • projects/ — Per-project memory and configuration
    • <project-path>/
      • CLAUDE.md — User-level project instructions (not committed to git)
      • memory/ — Persistent memory files Claude saves across sessions
  • keybindings.json — Custom keyboard shortcuts
Key point: The global ~/.claude/ directory stores your personal preferences, while project-level .claude/ directories keep project-specific context. Settings in settings.json control permissions, hooks, and automated behaviors.
📝

CLAUDE.md Files

CLAUDE.md is your way of giving Claude Code persistent instructions. Think of it as a README that Claude reads every time it starts a conversation in your project.

Project Root

./CLAUDE.md

Checked into git. Shared with your team. Contains build commands, code style rules, and project conventions.

User-level (per project)

~/.claude/projects/.../CLAUDE.md

Personal and not committed. Your own preferences, shortcuts, or overrides for this project.

Subdirectory

./src/CLAUDE.md

Scoped instructions for a subdirectory. Claude loads these when working in that folder.

What to put in CLAUDE.md

CLAUDE.md
# My Project

## Build & Test Commands
- Build: `npm run build`
- Test single file: `npm test -- path/to/file.test.ts`
- Lint: `npm run lint -- --fix`

## Code Conventions
- Use TypeScript strict mode everywhere
- Prefer functional React components with hooks
- Name files in kebab-case (e.g., user-profile.tsx)
- All API responses must use the Result<T> type

## Architecture Notes
- /src/api/ — REST handlers (Express)
- /src/services/ — Business logic layer
- /src/db/ — Prisma models and migrations

## Things to Avoid
- Never use `any` type
- Don't add console.log in production code
- Don't modify generated files in /src/generated/

Skills (Slash Commands)

Skills are reusable prompt templates that you invoke with slash commands. They encapsulate complex workflows into simple one-liners, turning multi-step tasks into a single command.

/commit
Analyzes your staged changes and creates a well-formatted git commit with an auto-generated message.
Built-in
/review-pr
Reviews a pull request for bugs, security issues, code quality, and provides actionable feedback.
Built-in
/fast
Toggles fast mode — same Opus model but with faster output. Great for quick tasks.
Built-in
/simplify
Reviews changed code for reuse, quality, and efficiency, then fixes any issues found.
Custom

How Skills Work

1
You type a slash command like /commit
2
Claude Code expands it into a full detailed prompt behind the scenes
3
Claude executes the task using the expanded instructions, tools, and context
Tip: You can create custom skills for your team's workflows — deploy scripts, test runners, code review checklists, and more. Skills are defined as prompt templates and registered in your configuration.
🤖

Agents (Sub-agents)

Agents are specialized Claude instances that can be spawned to handle specific tasks in parallel. They run independently with their own context and tools, then report back results.

Explore Agent

Fast codebase exploration — find files by patterns, search for keywords, answer structural questions about the code.

Use for: "How do API endpoints work in this project?"

Plan Agent

Software architect agent that designs implementation strategies, identifies critical files, and considers trade-offs.

Use for: "Plan how to add authentication to this app"

Code Review Agent

Thorough code reviewer that catches bugs, security issues, and over-engineering. Uses deeper analysis.

Use for: "Review my changes before I push"

General Purpose Agent

Handles complex, multi-step tasks. Can search code, read files, run commands — a full-powered Claude in a sandbox.

Use for: "Research how error handling works across the codebase"

Why Agents?

Parallelism

Multiple agents can run at the same time, speeding up research and multi-part tasks.

Isolation

Each agent has its own context window, keeping the main conversation clean and focused.

Specialization

Different agent types have different tools and strengths — the right agent for the right job.

Claude API Basics

Build AI-powered applications with the Anthropic API

Python SDK

Python
import anthropic

client = anthropic.Anthropic()

message = client.messages.create(
    model="claude-sonnet-4-6-20250415",
    max_tokens=1024,
    messages=[
        {"role": "user",
         "content": "Hello, Claude!"}
    ]
)

print(message.content[0].text)

TypeScript SDK

TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

const message = await client.messages.create({
  model: "claude-sonnet-4-6-20250415",
  max_tokens: 1024,
  messages: [
    { role: "user",
      content: "Hello, Claude!" }
  ],
});

console.log(message.content[0].text);

Key API Concepts

Messages API

The primary way to interact with Claude. Send a list of messages (user/assistant turns) and receive a response. Supports streaming for real-time output.

System Prompts

Set the behavior, personality, and constraints for Claude using a system prompt. This guides how Claude responds across the entire conversation.

Tool Use (Function Calling)

Define tools that Claude can call to interact with external systems - APIs, databases, calculators, etc. Claude decides when to use them and structures the arguments.

Vision (Multimodal)

Claude can analyze images passed in messages. Useful for understanding screenshots, diagrams, charts, documents, and more.

Prompt Caching

Cache frequently used prompt prefixes (like system prompts or large context) to reduce latency and cost on subsequent requests.

Extended Thinking

Enable Claude to think step-by-step before responding, improving performance on complex reasoning, math, and coding tasks.

Prompting Best Practices

Get better results from Claude with these techniques

1

Be Specific

Instead of "fix this code", say "fix the null pointer exception in the parseUser function on line 42 that occurs when the email field is missing."

2

Provide Context

Share relevant code, error messages, expected behavior, and what you've already tried. The more context Claude has, the better the answer.

3

Use Examples

Show Claude what you want with input/output examples. "Given input X, I expect output Y" is much clearer than a long description.

4

Break Down Complex Tasks

Instead of asking for an entire app at once, break it into steps: design the schema, then the API, then the UI, etc.

5

Assign a Role

"You are a senior backend engineer reviewing this PR for security issues" helps Claude adopt the right perspective and expertise level.

6

Iterate and Refine

Don't expect perfection on the first try. Use follow-up messages to refine, adjust, and improve Claude's output.
